# 冻结流程与千问办公提示词

版本：`qwen-review-v1.0.0`；日期：2026-09-08。

## 1. 在千问开任务，固定工具版本

由千问办公拉取 `https://github.com/janauto/work_skill.git`，检出
`qwen-review-v1.0.0`，记录实际 commit SHA。复现时使用 tag/commit，不依赖持续变化的 main。
运行兄弟技能的 `doctor.py` 与 `acceptance/run_acceptance.py`，记录缺失能力和跳过项。
已有同一版本的环境检查可复用。

将客户 STEP、BOM、参考版式放在仓库外。记录输入 SHA256、BOM 工作表/修订版、
本次关注结构与预期图纸类型。参考图只用于确定版式和解释深度，不能作为新产品结构证据。

可复制到千问的新任务 Prompt（替换方括号内输入）：

> 请在这个任务内完成硬件结构说明图项目。先从
> https://github.com/janauto/work_skill.git 拉取并检出 qwen-review-v1.0.0，
> 读取 qwen-patent-review/SKILL.md，按其流程调用兄弟技能的正式 CLI。
> STEP：[文件路径]；BOM：[文件路径]；重点：[例如电机与传动]；用途：[内部说明/教程]；
> 参考图：[文件路径]；期望图纸：[整机装配、整机爆炸、关键结构装配与分解、必要特写]。
> 原文件只读，产物保存在仓库外。先解析模型和 BOM，对照零件身份与数量，给出分图方案，
> 打开 Web 展示真实模型供我二次确认。得到我对本版本的确认后回到这个任务继续出图。
> 每页要有真实 CAD 主图、右上功能和装配说明、图下一句概述、左下零件表和图号。
> 零件表逐件解释作用与连接；不清楚的工艺写具体待核实项。编号沿用统一标记表，
> 同名不同零件不能合并。输出可编辑 DXF/DWG、PNG/PDF、逐页验收记录与易懂教程。
> 实际未完成的步骤和未识别的结构必须如实报告，不能只交过程文字。

## 2. 解析、识别、分图

1. 运行 `analyze_assembly.py`，对照 BOM；计数区分源实例数、有效实例数、空几何数、
   不同名称数。不同名称数不能直接叫“零件种类数”。保留稳定实例路径/索引，不能只用名字。
2. 对同名重复件逐个检查几何、尺寸与位置。无法区分时记录能力限制；不要把三件异形件写成用量 3。
3. 为每个实例建立“所在总图 / 所在分区图 / 是否有标号 / 对应表格行 / 排除依据”索引。
   CAD 存在但被外壳遮住，不等于细节已经解释；总图覆盖与可辨识覆盖分别记录。
4. 按功能和装配关系拆图。需要看到动力传递时，保留实际位置的局部装配图；分解图说明零件组成，
   不能单独证明啮合关系。小件做特写。图数由结构决定，不固定为 4、10 或 11 张。
5. 原 CLI 的标号策略是全局的；整机密集标号放不下时，可使用整体几何计划和局部标号计划。
   各计划的共同零件必须保留相同 terms 顺序、从同一标记表映射，检查号码一致后再交付。
   不为通过 QA 删除用户要求解释的功能件。

## 3. Web 二次确认

使用 `plan_studio.py` 提供的真实地址打开规划台。至少展示整机装配态、重点结构装配态、
分解态和一个细节视图。切换图后核对当前图名和可见零件；“选中零件”不等于切换当前图。
由用户确认结构范围和分图，记录原话、计划哈希与反馈时间。

工具反馈和用户反馈不同：截图正常、渲染完成、保存成功均不能代替用户确认。
若本轮修改了零件范围或结构解释，需要反馈修改后的版本；纯文件导出修正可说明后继续。

## 4. 回到千问生成说明图

千问按反馈更新计划，依次 validate → render → QA；使用固定的标记表填写
`review-sheets.json`，调用本目录的正式排版脚本。

右上说明回答“它做什么、为什么这样组合、谁和谁连接”；表格逐件回答“叫什么、几个、
起什么作用、装在哪里、如何固定”。缺少证据时明确“固定工艺待核实”，不能留空白备注。
先输出代表性一页并检查，再整套生成；复用已经确认的版式，不为不同页临时调整字号。

双计划的总图通常只有少量标号；其余条目如需列入表格，应注明未标引线原因并保持全局编号。
无法分实例标号的条目保留“—”及追踪记录，不通过手填新编号伪造工具能力。

## 5. 验收与交付

机器检查 → 打开最终 DXF 渲染的 PNG → 打开最终 PDF → DWG 转换与 AUDIT → 文件清单/哈希。
表格长时拆页或缩短文字；不能上移表格压住主图，也不能把中文缩成不可读的小字。
检查 PDF 实际纸张为 420 × 297 mm，不只看截图长宽比例。

检查引线锚点、编号、名称、数量、功能说明、装配说明逐一一致。
检查整机爆炸图等用户点名项确实存在；存在限制就放进“未完成/待确认”栏。
原始 CAD QA 通过不能认证新说明文字，DWG AUDIT 零错误也不能认证工程事实。

回到原千问任务，提供文件和实际检查结果。教程按“输入资料 → 千问执行 → Web 确认 →
千问交付”组织，配真实操作截图和能打开的成品。营销表达示例：
“把复杂硬件拆成一页页看得懂的结构说明，每个零件的作用、位置与待确认事项都有据可查。”
不要宣称已自动核定未验证的连接工艺、传动比或专利授权结论。

## 冻结依据与限制

本版来自一次真实的千问办公迭代：由局部图和过程报告改进到整机视图、功能分区及特写，
形成 11 页包含说明与零件表的交付稿；用户认可了表现效果。
版式样张由 Codex 制作，千问基于样张完成成套输出，此后在此仓库中整理为通用流程和排版工具。
这项记录不等于 11 页工程内容已全部核实，也不意味着本版应固定输出 11 页。

冻结时修正了样例脚本的 PDF 纸张尺寸问题，将表格名称和备注都纳入真实字体宽度测量，
增加内容非空、实例重复计数、源编号一致和溢出拦截。
基础 CAD 引擎保持不变；同名实例独立编号、自动判定固定工艺与自动认证全实例可辨识覆盖
仍未实现。部署到另一台机器后，应重新做字体、PDF 与 DWG 验证。
