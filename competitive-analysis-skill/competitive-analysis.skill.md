# 竞品分析 Skill

当用户要求对某个产品/项目进行竞品分析时，按照以下完整流程执行。最终输出一份结构化的 Markdown 竞品分析报告，保存到项目根目录。

---

## 触发条件

用户提到以下关键词时激活本 skill：
- "竞品分析"、"竞品调研"、"competitive analysis"
- "分析一下市面上类似的产品"
- "帮我做个市场调研"

---

## 执行流程

### 第一步：明确分析对象

向用户确认：
1. 你的产品是什么？（一句话描述定位）
2. 目标用户是谁？
3. 技术栈是什么？（如有）
4. 有没有已知的竞品名单？（没有的话我来找）

### 第二步：竞品识别与分类

通过 web 搜索 + GitHub 搜索，找到 5-8 个竞品，按以下维度分类：

| 类型 | 说明 |
|------|------|
| 直接竞品 | 定位几乎一样的产品 |
| 间接竞品 | 解决同一问题但方式不同 |
| 潜在威胁 | 大平台可能顺手覆盖的功能 |
| 参考标杆 | 不竞争但交互/设计值得学习 |

### 第三步：逐个竞品详细分析

对每个竞品输出以下表格：

```markdown
| 维度 | 说明 |
|------|------|
| 官网/来源 | URL |
| 定位 | 一句话 |
| 核心功能 | 3-5 个关键功能 |
| 技术栈 | 如可知 |
| 部署方式 | SaaS / 本地 / 混合 |
| 价格 | 免费 / 订阅 / 一次性 |
| 优势 | 2-3 点 |
| 劣势 | 2-3 点 |
| 与你的差异 | 一段话总结 |
```

### 第四步：UI 交互与设计风格分析

对每个竞品分析：
1. **窗口形态**：桌面 / Web / 命令面板 / 插件
2. **主导航模式**：侧边栏 / 顶栏 / 命令面板
3. **布局**：两栏 / 三栏 / 表格 / 会话式
4. **调用方式**：打开应用 / 全局快捷键 / 关键词触发
5. **视觉风格**：主色调、字体、信息密度、是否深色
6. **键盘优先程度**

归纳出几种典型交互范式，并给出对用户产品的具体建议（交互层 + 视觉层 + 反例）。

### 第五步：功能对比矩阵

用表格横向对比所有竞品的关键功能支持情况：
- ✅ 支持 | ⚠️ 部分支持 | ❌ 不支持 | 🔜 规划中

### 第六步：市场热度数据

通过 GitHub REST API 拉取开源竞品数据：
```bash
curl -s https://api.github.com/repos/{owner}/{repo} | grep -E '"stargazers_count"|"forks_count"|"open_issues_count"|"created_at"|"pushed_at"'
```

对闭源/商业竞品，通过 web 搜索获取：
- 用户量 / DAU
- 融资情况
- 团队规模

输出：
- 按 ⭐ 排序的数据表
- 对比参照（同生态的知名项目作为规模感参考）
- 四类竞品的"热度形态"解读
- 可视化坐标图（文本 ASCII）

### 第七步：用户需求与痛点挖掘

抓取高星竞品的 GitHub Issues 和 PRs：

```bash
# 按 👍 排序的 open issues
curl -s "https://api.github.com/search/issues?q=repo:{owner}/{repo}+is:issue+is:open+sort:reactions-%2B1-desc&per_page=15"

# 最近 merged 的 PRs
curl -s "https://api.github.com/search/issues?q=repo:{owner}/{repo}+is:pr+is:merged+sort:created-desc&per_page=15"
```

分析维度：
- 用户在喊什么？（高票未解决 issues）
- 维护者在做什么？（最近 merged PRs）
- 哪些功能被反复要求却没人做？
- 跨竞品的共性痛点归纳
- 从 Issues 里找到的产品机会

### 第八步：视觉素材收集

从竞品的 GitHub README 和官网抓取截图、动图：
1. 用 `web_fetch` 抓取 README 中的图片链接
2. 用 `curl` 下载到本地 `assets/competitors/<竞品名>/` 目录
3. 在报告中用相对路径引用，附来源链接
4. 每张图附"值得借鉴的点"和"不要照抄的点"

### 第九步：综合输出

最终报告结构：

```
# [产品名] 竞品分析报告
## 一、TL;DR（一句话结论 + 差异化机会）
## 二、竞品详细分析（逐个）
## 三、UI 交互模式与设计风格分析
## 四、竞品视觉素材库
## 五、竞品功能对比矩阵
## 六、市场热度数据分析
## 七、用户需求与产品痛点挖掘
## 八、核心竞争优势
## 九、竞品的可借鉴点
## 十、市场定位图（ASCII 坐标）
## 十一、功能清单（☐/☑ 勾选式 backlog）
## 十二、建议优先级路线图（Phase 1-4）
## 十三、数据来源
```

### 第十步：PRD 差距分析（可选）

如果用户已有 PRD，额外输出：
- PRD 已覆盖 vs 竞品分析新发现的 gap
- 建议新增的功能（按优先级）
- 建议重新考虑/删除的功能
- 3 条核心产品建议

---

## 输出规范

- 语言：跟随用户语言（中文用户输出中文）
- 格式：Markdown，保存为 `竞品分析报告.md`
- 图片：下载到本地 `assets/competitors/` 目录
- 数据：标注采集时间，注明来源链接
- 合规：不超过 30 个连续词的直接引用，超出部分改写

---

## 注意事项

- 每个步骤完成后可以向用户确认是否继续，或者一口气全部跑完
- 如果 GitHub API 有 rate limit，分批请求
- 闭源产品的数据以公开报道为准，标注"估算"
- 报告末尾提醒用户去功能清单勾选想做的功能
