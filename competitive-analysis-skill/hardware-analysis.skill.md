# 硬件产品深度调研 Skill

当用户要求对硬件产品进行深度调研时，按照以下流程执行。最终输出结构化的 Markdown 调研报告。

---

## 触发条件

用户提到以下关键词时激活本 skill：
- "硬件调研"、"硬件产品分析"、"hardware analysis"
- "深度调研XX设备"、"分析XX产品的硬件"
- "可穿戴设备调研"、"IoT产品分析"

---

## 执行流程

### 第一步：明确调研对象

向用户确认：
1. 调研哪个/哪些产品？
2. 调研目的是什么？（竞品分析/市场进入/技术学习）
3. 输出保存到哪个目录？
4. 是否需要与自有产品对比？

### 第二步：信息收集

通过 web 搜索收集以下信息：

| 信息类型 | 来源优先级 |
|----------|-----------|
| 产品规格 | 官网 spec 页 > gadgetsandwearables.com > 评测文章 |
| 价格信息 | 官网 > Amazon > 评测文章 |
| 公司背景 | Wikipedia > Crunchbase > 新闻报道 |
| 用户评价 | Amazon reviews > Reddit > 评测文章 |
| 市场数据 | CNBC/Bloomberg > TechCrunch > 行业报告 |

**搜索策略：**
- 第一轮：产品名 + specs/review/price
- 第二轮：公司名 + funding/valuation/users
- 第三轮：产品名 + vs + 竞品名（对比文章）

### 第三步：产品图片获取

**图片来源优先级：**
1. 官方博客 CDN（如 storage.googleapis.com）
2. 官方产品页
3. 媒体评测文章中的图片
4. Amazon 产品图

**图片处理流程：**
```bash
# 1. 下载图片
curl -L -s -o "Attachments/product-name.jpg" "URL"

# 2. 验证文件类型
file "Attachments/product-name.jpg"
# 期望输出: JPEG image data 或 RIFF...Web/P image

# 3. 验证文件大小
ls -lh "Attachments/product-name.jpg"
# 期望: > 10KB

# 4. 如果是 HTML 或 < 1KB，立即删除
rm "Attachments/product-name.jpg"
```

**失败回退策略：**
- 403/timeout → 尝试其他来源
- 所有来源失败 → 使用 ASCII 图表 + 外部链接引用
- **绝对禁止**使用 Unsplash/Pexels 等通用素材图替代

### 第四步：撰写调研报告

按以下结构输出：

```markdown
# [产品名] 硬件产品深度调研

## 一、分析概览
（表格：产品/公司/定位/价格/核心卖点/状态/日期/分析师）

## 二、公司背景
- 创立故事
- 发展里程碑
- 融资与估值

## 三、产品概述
- 产品定位
- 目标用户
- 差异化
- 产品线对比（如有多个SKU）

## 四、硬件规格
- 核心参数（尺寸/重量/续航/防水/材质）
- 传感器配置
- 充电方式
- 连接方式（BLE/WiFi/GPS）

## 五、商业模式
- 定价策略
- 订阅模式（如有）
- TCO 总拥有成本计算
- 配件生态

## 六、核心功能分析
- 功能拆解
- App/软件生态
- AI/算法能力

## 七、竞品对比
- 直接竞品对比表
- 价格矩阵
- 功能矩阵

## 八、市场表现
- 用户数据
- 收入/增长率
- 市场排名

## 九、SWOT 分析
- Strengths / Weaknesses / Opportunities / Threats

## 十、战略洞察
- 商业模式创新点
- 对中国企业的启示

## 十一、参考来源
- 所有引用的 URL + 日期
```

### 第五步：ASCII 图表制作

**必须遵循的规则：**

1. 代码块内**禁止**在 `|` 边框行内使用中文字符
2. 标签/标题使用英文，中文说明放在代码块外
3. 只使用纯 ASCII 字符: `+ - | = * o ~ < >`
4. **禁止** Unicode 特殊字符: `┌┐└┘├┤│─╭╰█░━◄►←→┼┬●▼▓`

**正确示例：**
```
Product Comparison

+-----------+    +-----------+    +-----------+
| Product A |    | Product B |    | Product C |
|           |    |           |    |           |
| $99       |    | $199/yr   |    | $359/yr   |
| 7-day bat |    | 14-day bat|    | 14-day bat|
| No ECG    |    | No ECG    |    | ECG       |
+-----------+    +-----------+    +-----------+
```

**错误示例（禁止）：**
```
| 产品A     |    | 产品B     |    <-- 中文导致右侧 | 错位
```

### 第六步：质量检查

完成报告后执行：
1. 检查所有图片链接是否可显示
2. 检查代码块内是否有中文+边框混用
3. 检查数据是否标注来源
4. 检查价格是否标注币种和时间

---

## 输出规范

- **语言**：正文中文，代码块内英文
- **格式**：Markdown，兼容 Obsidian
- **图片**：下载到本地 `Attachments/` 目录，使用 `![[filename]]` 引用
- **数据**：标注采集时间和来源链接
- **合规**：不超过 30 个连续词的直接引用

---

## 网络爬取容错策略

| 情况 | 处理方式 |
|------|----------|
| 普通 fetch 失败 | 尝试 rendered 模式 |
| rendered 超时 | 切换备用来源 |
| 403 Forbidden | CDN 防盗链，换来源 |
| 文件 < 1KB | 删除，标记为获取失败 |
| 文件类型为 HTML | 删除，不是图片 |
| 所有来源失败 | ASCII 图表 + 外部链接 |
| 搜索 snippet 已有足够信息 | 不必强制 fetch 全文 |

---

## 注意事项

- 硬件产品的规格数据以官方 spec 页为准
- 订阅制产品需计算 1年/3年/5年 TCO
- 传感器配置对比是硬件调研的核心差异点
- 市场数据优先使用最近6个月的报道
- 如果产品尚未发售，标注"预发布信息，可能变更"
